# 教材正文写作指南

本指南规定《线性代数及应用》的正文、例子、证明、小结和习题风格，主要依据已经完成的
前两章整理。编辑 `.tex` 文件前，应同时阅读 `../AGENTS.md` 和
`NOTATION_GUIDE.md`。

## 1. 写作定位

- 本书面向正在系统学习线性代数的读者，在数学严谨性和几何直观之间保持平衡。
- 内容通常按照“具体对象与直观 → 运算或现象 → 抽象定义 → 性质与定理 → 例子与应用”
  的顺序展开。
- 每一节围绕一个清晰问题推进，不把多个尚未建立联系的概念并列堆放。
- 编辑已有内容时遵循最小改动原则，保留作者的结构、语气和数学意图。

## 2. 中文表达

### 2.1 语气与句式

- 使用自然、克制、正式的现代汉语，避免口语化、宣传式表达和模板化 AI 腔。
- 先说明对象与结论，再给出解释。句子过长时应在逻辑转折处拆分。
- 主语必须明确。避免“对于一个向量组，其……”这类悬垂结构，优先写
  “向量组的……”或“对于一个向量组，……”。
- 条件使用“若……则……”；不要把“如”误作“若”。等价关系使用“当且仅当”。
- 能直接陈述时，不堆叠“值得注意的是”“特别需要注意的是”“有趣的是”“显然”
  “不难发现”等提示语。
- 同一段不要连续使用“此外”“因此”“并且”。连接词应体现真实的逻辑关系。
- 区分必然性与可能性。例如，应写“极大线性无关组可能不唯一”，不能写成
  “线性相关向量组的极大线性无关组不唯一”。

### 2.2 术语

- 术语必须与数学含义一致，不用近似词替代严格概念。
- “线性空间”作为主要名称，“向量空间”作为同义名称。
- 线性空间和子空间使用“维数”，有限向量组使用“秩”。
- “超平面”只用于余维为 \(1\) 的情形，不能泛指任意高维空间。
- “数乘”和“标量乘法”是同一概念。需要区分时，写“域中的乘法”和
  “标量作用于向量的数乘”。
- 术语首次正式出现时，可采用 `\textbf{向量}（Vector）` 的形式给出英文，
  后文不重复标注。

### 2.3 段落衔接

- 章首用一段话说明本章研究对象、主要问题和与前文的关系。
- 节首简要说明引入概念的动机，但不提前使用尚未定义的术语。
- 从具体对象推广到抽象结构时，应指出推广依赖哪些运算或规律。
- 定义之后可以补充直观解释、典型例子和用途，但不重复定义原文。
- 定理前说明它解决的问题；证明后只在确有必要时总结意义。

## 3. 数学严谨性

### 3.1 定义

- 明确底域、集合、运算、变量范围和量词顺序。例如，零向量公理要求先存在同一个
  零向量，再对所有向量成立。
- 定义数值不变量前先保证良定义性。例如，定义维数前应说明任意两组有限基所含
  向量个数相同。
- 注意有限与无限情形的范围。本书当前主要具体讨论有限向量组和有限基；提及无限基时，
  应明确这是更一般的定义。
- 零空间、空向量组、空集合和零维情形应与一般定义相容。
- 定义中不要使用尚未建立的性质，也不要把例子特有的运算当作一般运算。

### 3.2 定理与证明

- 定理写全底域、有限维条件、非空条件和共同环境空间。
- “两个线性空间的交”应表述为“同一线性空间 \(V\) 的两个子空间的交”。
- 集合相等通常分别证明两个包含关系。
- 证明映射同构时验证双射、加法保持和数乘保持。
- 反证法必须明确写出矛盾双方，不能把相容的包含关系称为矛盾。
- 使用归纳过程时写“归纳地，假设……”，不要用“不失一般性”代替归纳假设。
- 使用“任意”“存在”“唯一”时检查量词顺序；唯一性证明不能代替全局存在性条件。
- 核心结论不得仅以“证明简单，此处略去”带过；适合练习的基础验证可以移入习题。
- 引用前文结论使用 `\cref{...}`，并检查该结论的前提确实覆盖当前情形。

### 3.3 例子

- 例子必须真正满足所说明的定义，尤其检查零元、加法封闭和数乘封闭。
- 区分线性空间、线性子空间和仿射参数空间。首一多项式集合通常不是线性空间。
- 几何分类要排除退化对象，并让正文、公式、图片和图题保持一致。
- 例子中的数值应事先验算，避免无意退化、错误线性关系或不唯一坐标。
- 应用性例子服务于当前概念，不为展示背景知识而引入过多旁支。

## 4. LaTeX 写法

### 4.1 环境与标签

- 每章写在独立 `.tex` 文件中，由 `book.tex` 使用 `\include` 引入。
- 使用项目已有环境：`definition`、`theorem`、`proposition`、`lemma`、`property`、
  `example`、`proof` 和 `exercise`。
- 标签前缀统一如下：
  - 章、节：`chap_`、`sec_`；
  - 定义：`def_`；
  - 定理、命题、引理：`thm_`、`prop_`、`lem_`；
  - 例子、习题：`ex_`、`exer_`；
  - 图片：`fig_`。
- 所有标签名均不得包含冒号 `:`，各部分统一使用下划线 `_` 分隔，以便直接复制；
  `\label{...}` 与 `\cref{...}`、`\ref{...}` 等引用命令中的标签名必须完全一致。
- 使用 `\cref{label}` 交叉引用，不手写可能变化的编号。

### 4.2 公式与强调

- 行内公式使用 `\(...\)`，行间公式使用 `\[...\]`，不用 `$$...$$`。
- 多行推导使用 `aligned` 或 `split`，不靠手工空格对齐。
- 公式间距只使用 `\quad`，不使用 `\qquad`。
- 中文句子中的公式服从整句标点。公式结束句子时应有句号；公式后接“其中”
  “因此”等时，句法应保持连续。
- LaTeX 强调只使用 `\textbf{...}`，不要写 `\textbf{**...**}`。
- 不为了局部视觉效果加入与全书不一致的额外字体、颜色或空白命令。

## 5. 定义、定理与例子的组织

- 定义前先说明为什么需要该概念，定义本身保持紧凑。
- 一个定义环境主要定义一个概念；紧密成对的概念可以合并，例如线性相关与线性无关。
- 定理名称只在有稳定通用名称时添加，如“子空间判定定理”“交换定理”。
- 证明紧跟定理，不在二者之间插入无关说明。
- 例子应放在相关定义或结论之后，并在正文中解释它验证或展示了什么。
- 图形只在确实改善理解时使用；绘图要求见 `ASYMPTOTE_STYLE_GUIDE.md`。

## 6. 章末小结

一章末尾使用 `\section{小结}`，结构如下：

1. 先用一段话概括本章主线和抽象层次；
2. 使用 `enumerate` 列出与各节对应的主要内容；
3. 最后用一句话说明这些内容与后续章节的联系。

小结不逐条重复定义，不引入新定理，也不写成知识点索引。标签采用
`sec_<chapter>_summary`。

## 7. 习题

- 一章末尾使用 `\section{习题}`，标签采用 `sec_<chapter>_exercises`。
- 单题标签采用 `exer_<chapter>_<number>`，并按出现顺序连续编号。
- 难度通常按照“基本计算 → 概念判断 → 结构验证 → 证明题 → 综合题”递进。
- 题目只能直接使用正文已经定义的概念；若需引入新记号，必须在题目中当场定义。
- 题干应自足，变量范围、环境空间、底域和有限维条件必须明确。
- 不把“设”单独放在一行。简短条件直接并入题干；较长对象用完整句子引出，例如
  “在 \(\mathbb R^3\) 中定义集合”。
- 习题公式间距只使用 `\quad`。
- 多小问使用 `enumerate`；除最后一项用句号外，各项通常用中文分号结尾。
- 判断题要求“并说明理由”；证明题直接写“证明”。
- 证明题应覆盖本章的核心结构，并与计算题、判断题保持合理比例。
- 不在正文习题区附答案或提示，除非用户明确要求。

## 8. 修改后的自检

- 是否使用了尚未定义的术语？
- 定义的量词、底域、非空条件和有限维条件是否完整？
- 定理结论是否强于前提实际能够推出的内容？
- 证明中的“因此”和“矛盾”是否有明确依据？
- 例子是否真的满足相应代数结构？
- “维数”和“秩”是否使用正确？
- 是否误把“可能不唯一”写成“一定不唯一”？
- 是否出现 Markdown 强调、`$$...$$` 或 `\qquad`？
- 习题中是否有单独一行的“设”？
- 新增标签是否唯一，交叉引用是否可以解析？
